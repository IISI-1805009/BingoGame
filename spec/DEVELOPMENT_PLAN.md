# 織城戰線 Woven Rampart — Godot 開發計畫

> 本計畫以「先驗證核心好不好玩，再擴充內容與連網」排序。玩法範圍以 [GAME_DESIGN.md](GAME_DESIGN.md) 為準，技術邊界以 [TECH_ARCHITECTURE.md](TECH_ARCHITECTURE.md) 為準。

## 0. 範圍原則

- 首發平台：iOS、Android；桌面版只作開發與測試工具。
- 引擎／語言：Godot 4.x 最新穩定版、GDScript、2D `Control` UI。
- 第一個可玩版本只做單機垂直切片；PvP 不阻擋玩法驗證。
- 3–4 人派對對戰不納入首發，目前只保留設計，不建立程式分支。
- 每個階段都要有可執行產物與驗收門檻，不以「檔案已建立」視為完成。

## 目前進度（2026-08-21）

- **Phase 0：實作中**：已建立 Godot 專案設定、行動裝置／headless export preset、`game_core` 規則骨架、版本化平衡資料、固定 seed smoke tests 與 CI workflow。
- **Phase 0：驗證完成**：已用 Godot 4.7.1 headless 通過 6 組核心 smoke tests，並以 headless client 啟動主場景 2 frames；CI 仍會在乾淨 Linux runner 再執行一次。
- **Phase 1：核心程式完成、裝置驗收待辦**：已接上單機 Session、三段 AI 難度、雙方 5×5 盤面（敵方未認領格未知）、正確的第一手／跟色／第二動作狀態機、無合法跟色自動跳過、自由選擇／建設、跨動作多線倍率、攻擊 overlay、結算與重新開始；Action log 會記錄精確動作並可用 seed 重播驗證。Godot 4.7.1 headless 已通過核心測試與主場景啟動；剩餘 Phase 1 門檻是更完整的事件動畫，以及 Android／iOS 實機觸控驗收。
- **Phase 2：核心系統與 46 關資料完成、完整 playtest 待辦**：8 職業、11 張地圖、8 種天氣、20 道具均已接進 deterministic Session／replay。版本化本機存檔支援 legacy 升版、schema v1→v2 戰役進度遷移與壞檔安全恢復；玩家等級、城堡 Lv.1–40、8 職業訓練 Lv.1–10、首次／重複通關獎勵、逐關解鎖與完成輪數星等已落地。全 46 關會依章節套用職業池、稀有度、AI 城堡／難度／道具與二／三星輪數門檻，Stage 1 有分步教學，Stage 46 實作終焉庇護。主城→可捲動戰役地圖→戰鬥→結算／下一關→養成已形成可玩閉環，目前 23 組核心測試（含逐一初始化 46 關）與主場景啟動通過；剩餘 Phase 2 門檻為從新存檔到終章的完整內部 playtest，以及 Stage 1／46 優先的難度與星等門檻調整。

## Phase 0 — 專案骨架與規格測試化

**產出**

- 建立 Godot 專案、目錄邊界、autoload、輸入映射與 Android／iOS／Linux Server export presets。
- 建立 GDScript 測試環境與 CI 基本流程。
- 把平衡參數移到資料檔／Resource，定義 `schemaVersion`。
- 從 Python 模擬器挑出固定案例，建立 GDScript golden tests。

**完成條件**

- 空白 client 可在桌面、Android 實機、iOS 實機啟動。
- Linux headless build 可啟動並通過 core 測試。
- PR／提交可自動執行無畫面的測試命令。

## Phase 1 — 單機核心垂直切片

**只做一張地圖、五職業、無道具的完整一局**，先把核心手感跑通。

**產出**

- 5×5 雙盤面、認領、跟色、自由選擇／建設、連線清除重填。
- 傷害／回復、稀有度、DEF、同色與多線加成、勝負。
- 基礎 AI、最小戰鬥 UI、事件驅動動畫、重新開始。
- Seeded RNG、Action log、可重播同一局。

**完成條件**

- 規則單元測試涵蓋所有基礎分支，包含雙方出擊戰力抵消、戰力相等時同歸於盡與倖存部隊攻城。
- 固定 seed 的 GDScript 結果與 Python 參考案例一致。
- 可在兩個行動平台完整玩完一局，沒有只能靠滑鼠完成的操作。

## Phase 2 — 完整 PvE 系統

**產出**

- 8 職業與被動、11 地圖、8 天氣、20 道具。
- 單機 AI 難度參數、教學關 Stage 1、終章 boss 特例。
- 本機版本化存檔、城堡／訓練所養成、戰功點數。
- 主選單、戰役、養成、戰鬥、結算、設定的功能性 UI。

**完成條件**

- 20 個道具與所有天氣均有規則測試；存檔升版與壞檔恢復測試通過。
- 先做代表性關卡（1、5、10、25、45、46）驗證難度曲線，再批次填入 46 關資料。
- 至少完成一次從新存檔到終章的內部 playtest，不得有進度阻斷。

## Phase 3 — 行動裝置體驗與內容製作

**產出**

- 響應式版面、安全區、觸控回饋、背景／前景切換處理。
- 美術、音效、動畫、在地化與無障礙的第一版規格落地。
- 46 關內容呈現、敘事包裝與實機 playtest 後的基本難度調整。

**完成條件**

- 目標中低階 Android 與支援範圍內最舊 iPhone 達到既定 FPS／記憶體門檻（數值在取得測試機清單後訂定）。
- 主要畫面無安全區裁切，網路中斷或 App 切背景不造成存檔毀損。
- 新玩家能不靠開發者解說完成教學與前三關。

## Phase 4 — PvP 與帳號服務

**進入條件**：核心玩法及單機留存訊號值得繼續投入，且第 0–3 階段的 core API 已穩定。

**產出**

- 選定 meta backend，完成 guest／正式帳號、雲端進度、榮譽點數與解鎖。
- Godot headless Match Server、配對、開局選擇、15 秒計時、超時代打。
- `MatchView` 資訊遮罩、Action 去重、狀態版本、斷線重連、結果冪等寫入。
- 伺服器 action replay、稽核 log 與基本營運監控。

**完成條件**

- client 無法藉封包取得對手**未認領格**資料，亦無法自行決定亂數、傷害或獎勵；已認領角色的公開資料在雙方畫面一致。
- 通過斷線、重連、重送、timeout race、程序重啟策略與弱網測試。
- 至少一次封閉測試驗證配對成功率、平均等待、平均局長與異常局比例。

## Phase 5 — 上線準備

**產出**

- 效能／耗電／流量調校、crash reporting、隱私與刪除帳號流程。
- 商店素材、簽章、版本號、分階段 rollout 與回滾方案。
- 數值與內容 remote config（若採用）需有版本、驗證與回滾，不允許直接破壞進行中的對局。

**完成條件**

- iOS TestFlight 與 Google Play 內部測試通過完整驗收清單。
- 後端容量、備份、告警、客服補償流程與事故處理手冊到位。

## 目前規格確認結果
